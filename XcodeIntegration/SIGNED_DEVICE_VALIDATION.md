# Signed Real-Device Validation

The unsigned V14 baseline is fixed at `00e3cc3a09b83946e728d7431b310d5ae5c2afd6` and remains unchanged in behavior.

## Required Apple-side setup

Create and register five explicit identifiers under one Apple Developer Team:

- `WT_HOST_BUNDLE_ID` for the Host App
- `WT_KEYBOARD_BUNDLE_ID` for the Keyboard Extension
- `WT_SHARE_BUNDLE_ID` for the Share Extension
- `WT_WIDGET_BUNDLE_ID` for the Widget
- `WT_VOICE_ACTIVITY_BUNDLE_ID` for Voice / Live Activity

Enable the App Group `$(WT_APP_GROUP_ID)` on every target. Enable the capabilities required by the Widget and Live Activity extensions. The bundle ID and App Group values must match the provisioning profiles generated by Xcode.

## Local Mac flow

1. Use a Mac signed into Xcode with a legal Apple Developer Team. Do not commit credentials or private signing material.
2. Export `DEVELOPMENT_TEAM`, the five Bundle ID variables, and the registered `WT_APP_GROUP_ID`.
3. Connect and trust an iOS 17 or newer iPhone, then export `DEVICE_UDID`.
4. Run `XcodeIntegration/signed_device_build.sh`.
5. Install the resulting app from Xcode Devices and Simulators.

## Phase-one acceptance

Validate only this path before expanding scope:

`Signed Build -> Install on iPhone -> Enable Keyboard -> Switch Keyboard -> Type Pinyin -> Candidates -> Commit Text`

Do not begin Share, Widget, or Voice / Live Activity behavioral validation until the Host App and Keyboard Extension input path passes.

Certificates, profiles, Team IDs, device UDIDs, and private provisioning data must not be committed.

GitHub-hosted macOS runners cannot attach your physical iPhone. The signed build must run on a Mac with the device connected and trusted, using Xcode automatic signing or locally installed provisioning profiles.

## Blocker policy

Mechanical certificate, profile, identifier, capability, or provisioning failures may be repaired within this workstream.

If installation reveals a Keyboard Extension crash, Rime initialization failure, candidate or commit-text error, App Group state divergence, or lifecycle problem, record the device model, iOS version, reproduction steps, crash/device logs, and observed state. Stop before architectural changes and hand the blocker to ChatGPT / GPT-5.6 Sol High. Do not redesign the input state machine or Hamster/librime core in this phase.
