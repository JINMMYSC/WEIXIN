# Signed Real-Device Validation

The unsigned V14 baseline is fixed at `00e3cc3a09b83946e728d7431b310d5ae5c2afd6` and remains unchanged in behavior.

## Required Apple-side setup

Create and register these identifiers under one Apple Developer Team:

- `$(WT_BASE_BUNDLE_ID)`
- `$(WT_BASE_BUNDLE_ID).keyboard`
- `$(WT_BASE_BUNDLE_ID).share`
- `$(WT_BASE_BUNDLE_ID).widget`
- `$(WT_BASE_BUNDLE_ID).voiceactivity`

Enable the App Group `$(WT_APP_GROUP_ID)` on every target. Enable the capabilities required by the Widget and Live Activity extensions. The bundle ID and App Group values must match the provisioning profiles generated by Xcode.

## Local Mac flow

1. Open `XcodeIntegration/Config.xcconfig` in a private local copy and set `DEVELOPMENT_TEAM`, `WT_BASE_BUNDLE_ID`, and `WT_APP_GROUP_ID`.
2. Connect and trust an iPhone, then set `DEVICE_UDID`.
3. Run `XcodeIntegration/signed_device_build.sh`.
4. Install the resulting app from Xcode Devices and Simulators, then enable the keyboard in Settings.
5. Validate Host App -> Keyboard input, Share, Widget, and Voice/Live Activity in that order.

Certificates, profiles, Team IDs, device UDIDs, and private provisioning data must not be committed.

GitHub-hosted macOS runners cannot attach your physical iPhone. The signed build must run on a Mac with the device connected and trusted, using Xcode automatic signing or locally installed provisioning profiles.

## Blocker policy

If signing, App Group, extension lifecycle, Hamster/librime, input-state, or real WeType behavior differs, record the exact device/log evidence and stop at the boundary. Do not redesign the input state machine or Hamster/librime core in this phase.
