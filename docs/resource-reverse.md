# 资源逆向证据（3.5.3）

本记录只保存对解包副本的静态分析结论，不包含原始 IPA、腾讯二进制或词库文件。

## 已确认

- `editpinyin.bin` 不是普通文本词表。当前可稳定解释为：`u32 n`、`u32 key/hash[n]`、`u16 end[n]`、变长 payload。21,486/21,487 条记录通过边界、单调性和长度公式检查，最大 `n` 为 9。
- `prism_v2.bin` 不符合当前 `0x80000001` 索引资源解析器的标准容器形态；静态扫描显示状态表、拼音字母区域和哨兵索引区域。不能直接把它当作已解析词库。
- `lmcn.bin` 使用另一种记录布局。首字段不能在没有更多装载代码证据时直接解释成分数或计数。
- 解包产物中没有明确的 `Rime`、`librime`、`RimeApi` 或 `RimeSession` 痕迹。已有线索更接近 `wxkb_plugin` 内的 `KBIMEMgr`、`KBIMESession` 和 `wxime` C++ 引擎。

## 当前工程边界

`IndexedResource` 只负责已确认的通用索引容器校验；`ResourceLoader` 会把缺失和格式错误分别报告。`TablePinyinEngine` 是注入式测试适配器，不能冒充原版候选排序。未确认字段、压缩解码和运行时模型参数均保留为待验证项。

## 下一步证据

1. 将资源文件偏移与 `wxime` 初始化、会话创建和候选请求的交叉引用对应起来。
2. 对 `editpinyin.bin` payload 建立少量已知输入的解码样本，避免无证据批量生成词条。
3. 由原版设备记录候选顺序、分页和学习前后差异，再决定哪些字段值得实现。
